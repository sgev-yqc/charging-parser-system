# 充电报文解析系统 — 整体设计方案

> 版本：v1.0 | 日期：2026-05-25 | 状态：待确认

---

## 一、系统定位

面向充电桩运维/数据分析团队的 **CAN报文解析与管理平台**，用于：
- 解析融合控制器的 GB/T 27930 协议报文
- 万级订单的存储、检索与查看
- 报文阶段分布、故障定位
- 数据导出（Excel/JSON/TXT）

---

## 二、技术栈

| 层级 | 技术 | 说明 |
|------|------|------|
| 前端/后端 | **Streamlit** | Python 全栈框架，快速迭代 |
| 存储 | **SQLite** → 后续可升 MySQL | 当前万级够用，扩展可换 |
| 解析引擎 | **用户自研 Python 协议库** | GB/T 27930 完整解析 |
| 部署 | **腾讯云服务器** | 生产环境目标 |
| 容器化 | **Docker**（可选） | 便于环境一致性 |

## 五、数据库设计

### 5.1 orders 表（订单主表）

```sql
CREATE TABLE orders (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    order_id    TEXT    UNIQUE NOT NULL,    -- 订单号（如 13404900000009670025031803200267）
    device_name TEXT    NOT NULL,            -- 充电桩编号
    file_name   TEXT    NOT NULL,            -- 原始文件名
    file_size   INTEGER DEFAULT 0,          -- 文件大小(bytes)
    total_stages   INTEGER DEFAULT 0,       -- 总阶段数
    total_messages INTEGER DEFAULT 0,       -- 总报文数
    parse_status   TEXT   DEFAULT 'pending', -- pending/success/partial/failed
    error_msg      TEXT,                     -- 解析错误信息
    file_path      TEXT,                     -- 原始文件存储路径
    created_at     DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at     DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

### 5.2 messages 表（报文明细表）

```sql
CREATE TABLE messages (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    order_id      TEXT    NOT NULL REFERENCES orders(order_id),
    stage_id      INTEGER NOT NULL,          -- 阶段序号
    stage_name    TEXT,                       -- 阶段名称
    msg_index     INTEGER,                   -- 报文序号
    timestamp_ms  REAL,                      -- 相对时间戳(ms)
    source        TEXT,                      -- CH（充电机）/ BM（BMS）
    can_id        TEXT,                      -- CAN ID
    data_hex      TEXT,                      -- 原始 HEX 数据
    parsed_name   TEXT,                      -- 解析后的参数名
    parsed_value  TEXT,                      -- 解析后的数值
    parsed_unit   TEXT                       -- 单位
);

CREATE INDEX idx_messages_order_id ON messages(order_id);
CREATE INDEX idx_messages_stage   ON messages(order_id, stage_id);
```

### 5.3 关键查询场景（对应索引策略）

| 场景 | SQL | 索引 |
|------|-----|------|
| 订单列表 | `SELECT * FROM orders ORDER BY created_at DESC` | created_at |
| 按桩筛选 | `WHERE device_name = ?` | device_name |
| 订单详情 | `WHERE order_id = ?` | order_id (PK) |
| 阶段分布 | `WHERE order_id = ? GROUP BY stage_id` | (order_id, stage_id) |
| 时间搜索 | `WHERE created_at BETWEEN ? AND ?` | created_at |
| 全文搜索 | `WHERE order_id LIKE ? OR device_name LIKE ?` | 需 LIKE，可用前缀索引 |

## 六、页面路由与交互流

### 6.1 路由设计

```
?page=home          → 首页 Dashboard（待实现）
?page=list          → 订单列表页 ★ 默认落地页
?page=detail&id=X  → 订单详情页
?page=upload       → 上传页
?page=search       → 高级搜索（待实现）
?page=compare&ids=  → 多订单对比（待实现）
```

### 6.2 核心交互流

```
上传报文文件 ──→ 自动解析 ──→ 跳转到列表页（最新订单在顶部）
                                        │
                                  点击「查看」
                                        │
                                        ▼
                                   订单详情页
                    ┌──────────────────┼──────────────────┐
                    ▼                  ▼                  ▼
               查看阶段分布       查看报文明细          导出数据
               （饼图/柱图）      （可筛选表格）    (Excel/JSON/TXT)
```

### 6.3 页面布局规范

**列表页：**
- 顶部：搜索框 + 桩编号筛选器 + 时间范围选择
- 中间：统计摘要行（总订单数/总桩数/总报文数）
- 主体：分页表格，每行含操作列（查看按钮）

**详情页：**
- 顶部：返回按钮 + 订单基本信息卡片
- 中间：阶段分布图 + 统计数字
- 底部：报文明细表格（可分阶段筛选、可滚动）

**上传页：**
- 拖拽/点击上传区域
- 上传后自动触发解析
- 解析完成跳转列表页
